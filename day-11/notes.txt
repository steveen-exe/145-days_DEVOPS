# Day 11 – Linux Storage Management (LVM)

## Objective

Today we learned **Logical Volume Manager (LVM)**, one of the most important storage technologies for DevOps, SRE, and Cloud Engineers. LVM provides a **flexible virtual storage layer** that allows storage to grow, shrink, and span across multiple physical disks without major downtime.

---

# Why LVM?

Traditional Linux storage follows this structure:

```text
Disk
 └── Partition
      └── Filesystem
```

### Limitations

If a partition becomes full:

* Difficult to expand
* May require downtime
* Sometimes impossible to resize

LVM solves these limitations by introducing a virtualization layer between the physical disks and the filesystem.

---

# What is LVM?

**Logical Volume Manager (LVM)** creates a **virtual storage pool** by combining one or more physical disks.

Benefits:

* Expand storage easily
* Shrink logical volumes (supported filesystems only)
* Combine multiple disks into one storage pool
* Better storage utilization
* Online storage expansion with little or no downtime

---

# LVM Architecture

```text
             Disk (Brick)
                  │
                  ▼
      Physical Volume (PV)
      (Prepared Brick)
                  │
                  ▼
       Volume Group (VG)
      (Box of Bricks)
                  │
                  ▼
      Logical Volume (LV)
           (Wall)
                  │
                  ▼
          Filesystem
      (Paint on the Wall)
                  │
                  ▼
          Mount Point
```

Another way to visualize it:

```text
Disk(s)
   │
   ▼
Physical Volume(s)
   │
   ▼
Volume Group
   │
   ├── Logical Volume 1
   ├── Logical Volume 2
   └── Free Space
```

**Best Practice**

Do **not** allocate the entire Volume Group to a Logical Volume. Leave some free space for future expansion.

---

# LVM Components

## 1. Physical Volume (PV)

A **Physical Volume** is a disk or partition that has been initialized for LVM.

Example devices:

```text
/dev/sdb
/dev/sdc
/dev/sdd
```

Create a Physical Volume:

```bash
sudo pvcreate /dev/sdb
```

Display Physical Volumes:

```bash
sudo pvs
sudo pvdisplay
```

**Note**

Running `pvcreate` writes an **LVM label** onto the disk, preparing it to become part of an LVM storage pool.

---

## 2. Volume Group (VG)

A **Volume Group** is a storage pool created by combining one or more Physical Volumes.

Example:

```text
Disk 1 = 20 GB
Disk 2 = 30 GB

Volume Group = 50 GB
```

Create a Volume Group:

```bash
sudo vgcreate data_vg /dev/sdb
```

Display Volume Groups:

```bash
sudo vgs
sudo vgdisplay
```

---

## 3. Logical Volume (LV)

A **Logical Volume** is a virtual partition created from the available space inside a Volume Group.

This is where files are actually stored.

Using the wall analogy:

* PV = Bricks
* VG = Box of Bricks
* LV = Wall built from those bricks

Since the wall is virtual, it can easily become larger or smaller.

Create a Logical Volume:

```bash
sudo lvcreate -L 5G -n data_lv dev_vg
```

Display Logical Volumes:

```bash
sudo lvs
sudo lvdisplay
```

---

# Creating an LVM Storage

## Step 1 – Create a Physical Volume

```bash
sudo pvcreate /dev/sdb
```

---

## Step 2 – Create a Volume Group

```bash
sudo vgcreate dev_vg /dev/sdb
```

---

## Step 3 – Create a Logical Volume

```bash
sudo lvcreate -L 5G -n data_lv dev_vg
```

---

## Step 4 – Create a Filesystem

```bash
sudo mkfs.ext4 /dev/dev_vg/data_lv
```

---

## Step 5 – Create a Mount Point

```bash
sudo mkdir /data
```

---

## Step 6 – Mount the Filesystem

```bash
sudo mount /dev/dev_vg/data_lv /data
```

# Production Scenario – Filesystem is Full

Imagine your application has completely filled the storage.

Instead of creating a new partition and migrating data:

## Step 1 – Add a New Disk

Example:

```text
/dev/sdc
```

Initialize it as a Physical Volume:

```bash
sudo pvcreate /dev/sdc
```

---

## Step 2 – Extend the Volume Group

```bash
sudo vgextend dev_vg /dev/sdc
```

Now the Volume Group has additional free space.

--
## Step 3 – Extend the Logical Volume

Use all remaining free space:

```bash
sudo lvextend -l +100%FREE /dev/dev_vg/data_lv
```

Or extend by a specific size:

```bash
sudo lvextend -L +5G /dev/dev_vg/data_lv
```

---

## Step 4 – Resize the Filesystem

For **ext4**:

```bash
sudo resize2fs /dev/dev_vg/data_lv
```

For **XFS**:

```bash
sudo xfs_growfs /data
```

---

## Step 5 – Verify

```bash
df -h
```

# Key Takeaways

* LVM adds a virtualization layer between disks and filesystems.
* Physical Volumes (PV) are combined into a Volume Group (VG).
* Logical Volumes (LV) are created from the Volume Group.
* Filesystems are created on Logical Volumes.
* LVM allows storage to be expanded without repartitioning disks.
* Always leave free space in the Volume Group for future growth.
* LVM is widely used in enterprise Linux servers because it simplifies storage management and minimizes downtime.
